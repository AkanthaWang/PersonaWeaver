# 精简人物大事与合并关系

## 目标

- 人物详情用简短的重要经历代替逐项事实依据，并展示可信的相关章节。
- 同一对人物的多种关系合并展示，覆盖人物详情、关系列表和图谱。
- 保留约 200 字档案描述、头像和现有数据，不改动工作区已有 README 修改。

## 方案

- 从逐章人物资料中的 key_events 提取大事及其章节，去重并保留多章来源。
- 前端只显示关键经历，默认显示六项，可展开剩余内容；不再铺开属性、台词、版本和证据原文。
- 按人物 ID 配对合并关系，关系类型去重，保留底层记录和方向信息。
- 执行针对性数据测试、前端构建及浏览器验证。

## 结果

- 人物详情以“人物大事”代替逐项事实依据，单项最多展示 90 字，默认六项，可展开；移除冗长补充档案和版本、台词等逐项内容。
- 大事优先使用逐章 key_events，合并重复经历及其章节；手工补充经历不会覆盖自动提取内容。缺少可信来源时显示“章节未标注”，不套用人物首章。章节链接支持打开原文。
- 关系按人物 ID 配对合并，类型去重；详情按对方人物展示头像和关系组合，列表及图谱同步合并。保留底层记录，悬停可查看关系方向。
- 抽屉使用独立页脚，避免操作按钮遮住最后一行关系。
- 新增后端 `presentation.py`、前端 `characterPresentation.js` 及对应测试；人物查询接口增加 milestones 字段。
